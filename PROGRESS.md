## Phase 4 — investigation (un agent, ≤ 5 étapes, citations vérifiées) — livrée (2026-09-18)
- [x] **`lib/agent/`** — la Phase 4 telle que le PRD la définit (US-09, AC1–AC3) : un **seul** agent, borné à **5 étapes**, qui approfondit une suggestion et dont **toute citation est vérifiée programmatiquement** avant d'être affichée.

## Pièges d'environnement (rencontrés, à connaître)
- **Playwright/pilotage navigateur (2026-09-18)** : `playwright-core` ne télécharge aucun navigateur — ajouter la devDependency suffit si un Chromium est déjà dans `%LOCALAPPDATA%\ms-playwright` ; **les versions doivent correspondre** (1.63 attend chromium-1243, le cache avait 1208 → passer `executablePath` explicite au `launch`). Les captures du prérendu « networkidle » ne fonctionnent pas sur les pages qui sondent l'état (atelier) : poller côté Node.
- **Un écran jamais ouvert dans un navigateur peut planter au premier chargement** (React #185, maximum update depth) alors que build, tests et prérendu passent : `useSyncExternalStore` exige un snapshot **stable** (`Object.is`) — un objet fabriqué à chaque lecture boucle. Corrigé dans `synthesis-feed.tsx` (voir Phase 5B).
- **Le worker local est plus rapide que le HTTP** : sur un job qui se rejoue depuis le cache (~100 ms), le POST `/investigate` reçoit `ERR_ABORTED` côté navigateur (le serveur a répondu 202 avant la fin du fetch, ou la page a navigué) — bénin, à ne pas compter comme une requête en échec.
- **Next.js n'écrase jamais `process.env`** : une variable exportée dans le shell (ici `GROQ_CHAT_MODEL`, `GROQ_API_KEY`) prend le pas sur `.env.local`. Symptôme observé : le modèle « par défaut du schéma » était utilisé malgré un `.env.local` correct → `freebuff`/serveur à relancer avec `unset GROQ_* LLM_CHAT_PROVIDER` ou `env -u …`.
- **Le HMR de `next dev` tue le worker** : éditer un fichier pendant un run discover laisse le job `running` avec un lease périmé et sans aucun log (le process HTTP, lui, répond). Ne pas éditer pendant un run, ou redémarrer ensuite ; le reaper finit par récupérer le job.
- **Un glisser synthétique n'est pas un geste humain** : Playwright/Chromium **abandonnent** les `pointermove` quand le fil principal travaille (mesuré : 1 mouvement livré sur 12 → un delta de 1/12 écrit en base). Espacer les pas d'une image (`waitForTimeout(24)`) et repartir d'une page au repos après une action lourde avant de mesurer un geste.
- **`page.on("request")` peut manquer une requête** sous charge (constaté sur un `PATCH` qui avait bien été écrit en base) : mesurer les appels **côté page** (`window.fetch` instrumenté par `addInitScript`) quand la preuve porte sur « combien de requêtes ».
- **Quotas LLM gratuits** : le TPD Groq est par modèle mais le compte se fait throttler globalement (`Retry-After` 1 500 s observés) ; Mistral `free` peut être à `x-ratelimit-limit-req-minute: 0` sur un compte donné ; OVHcloud anonyme = ~1 requête sur 4 ; les gateways communautaires (LLM7, Kilo) sont instables. Toujours vérifier le modèle *exact* disponible (un id inconnu renvoie un 404 texte qui ressemble à une panne réseau).

## Ideas
- **Juge sémantique de conclusion pour l'investigation** (suite de la réserve 2 de la Phase 4) : la juxtaposition **vide** est désormais coupée (`conclusion-v2`), mais rien ne juge si la relation énoncée est juste — une conclusion qui ajoute « trouve son équivalent » à un récit « l'un …, l'autre … » passe. Il faut une grille (modèle + lecture humaine), mesurée comme l'a été la 5A, ou un durcissement itéré comme en 2A.
- Bouton « Voir le texte » d'une source (lecture du raw_content) pour vérifier les locators
- Pagination/limite sur la table bibliothèque pour gros corpus
- Observabilité : logger les erreurs de job côté serveur (aujourd'hui elles ne sont visibles qu'à l'échec final, dans la DB)
- Surveiller l'événement `SQLITE_NOMEM` transitoire (observé 1× sur GET liste pendant ingestion, non reproduit ; si récidive : `cache_size` + pagination)
